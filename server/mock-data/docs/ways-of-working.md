# Ways of working on delivery teams

> Fictional guide for demo purposes.

- **Sprints:** most teams run one- or two-week sprints with planning, daily stand-up, review and retro.
- **Stand-up:** say what you did, what you will do, and anything blocking you. Blockers are raised early, not saved for later.
- **Definition of done:** code reviewed, tests passing, acceptance criteria met, ticket updated.
- **Code review:** keep pull requests small. Review others' work within one working day.
- **Asking for help:** if you are stuck for more than an hour, ask your buddy or tech lead. Nobody expects new joiners to know everything.
